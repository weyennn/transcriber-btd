# Audit Anti-Slop UI 001

Tanggal audit: 2026-09-17
Mode: AFTER
Scope: dashboard web pada `src/web/templates/index.html`, `src/web/static/style.css`, dan `src/web/static/app.js`.

## Design Read

Reading this as: dashboard transkripsi audio lokal untuk staf non-teknis, dengan bahasa visual Pandora yang hangat dan editorial, dial ENERGY 2 / RHYTHM 2 / MOTION 2.

Catatan: tidak ditemukan `DESIGN.md` atau dokumen arah visual terpisah di repository. Dial di atas adalah pembacaan audit terhadap source yang ada, bukan arahan produk yang telah disahkan.

## Temuan

### 1. [HIGH] Alur transkripsi tidak pernah aktif setelah file dipilih

- Rule: R-26, R-35, C-2.
- Evidence: `selectedFile` dimulai sebagai `null` di `app.js:29`. Fungsi `setFile()` di `app.js:132-151` memvalidasi dan menampilkan file, tetapi tidak pernah menjalankan `selectedFile = file`. Listener tombol di `app.js:185-186` langsung berhenti saat `!selectedFile`, sehingga tombol `Mulai transkripsi` tetap disabled.
- Impact: pengguna dapat memilih file secara visual, tetapi tidak dapat memulai pekerjaan utama dashboard.
- Suggested fix: set state file yang dipilih di `setFile()` dan pastikan state file invalid menghapus atau tidak mempertahankan pilihan sebelumnya.

### 2. [HIGH] Item riwayat tidak dapat dipilih dengan keyboard

- Rule: R-32, R-26, C-4.
- Evidence: item dibuat sebagai `<li>` di `app.js:442-489`; pemilihan hasil hanya dipasang lewat `li.addEventListener("click", ...)` di `app.js:477-488`. Item tidak memiliki `role`, `tabindex`, atau handler Enter/Space.
- Impact: pengguna keyboard tidak dapat membuka hasil lama, meskipun tombol hapus di dalam item memiliki target keyboard sendiri.
- Suggested fix: gunakan kontrol native untuk nama hasil, atau tambahkan pola keyboard yang lengkap dengan role, focus state, dan Enter/Space.

### 3. [HIGH] Panel riwayat tidak memiliki loading dan error state yang terlihat

- Rule: R-27, C-4.
- Evidence: `refreshHistory()` di `app.js:431-494` mengosongkan daftar setelah respons sukses dan hanya menampilkan `Belum ada hasil.` untuk empty state. Saat gagal, fungsi hanya menulis `Riwayat gagal dimuat. Silakan coba lagi.` ke log di `app.js:491-493`; panel riwayat sendiri tidak menjelaskan status atau menyediakan aksi pemulihan.
- Impact: pengguna tidak dapat membedakan riwayat sedang dimuat, benar-benar kosong, atau gagal diambil dari server.
- Suggested fix: tambahkan state loading, empty, dan error di dalam panel riwayat. Error harus punya tindakan retry yang benar-benar memanggil refresh.

### 4. [HIGH] Overlay pembuka menyatakan diri sebagai dialog, tetapi fokus tidak dikelola sebagai dialog

- Rule: R-32, R-26, C-4.
- Evidence: `#portal-intro` memakai `role="dialog"`, `aria-modal="true"`, dan `aria-labelledby` di `index.html:11`. Fokus hanya diarahkan ke tombol masuk di `app.js:548`; setelah overlay disembunyikan di `app.js:536-540`, tidak ada pemindahan fokus ke dashboard dan tidak ada focus trap selama dialog terbuka.
- Impact: pembaca layar dan pengguna keyboard dapat kehilangan konteks fokus setelah overlay ditutup; elemen di belakang dialog tetap berada dalam urutan fokus sebelum masuk.
- Suggested fix: kelola fokus awal, fokus akhir, Escape, dan pemindahan fokus ke heading atau kontrol utama dashboard setelah dialog ditutup. Jika overlay bukan dialog interaktif penuh, gunakan struktur semantik yang lebih tepat.

### 5. [HIGH] UI tidak diberi arah desain yang terdokumentasi atau label draft

- Rule: R-37, R-20, R-31.
- Evidence: pencarian repository tidak menemukan `DESIGN.md` atau `design.md`. Source memiliki komentar gaya singkat di `style.css:36`, tetapi tidak menetapkan identitas, tipografi, dial ENERGY/RHYTHM/MOTION, atau alasan keputusan visual. Tidak ada label pengguna `draft without direction`.
- Impact: arah visual tidak dapat direview sebagai keputusan produk dan mudah berubah menjadi default agent tanpa pemilikannya jelas.
- Suggested fix: tambahkan arah desain yang disahkan pemilik, atau label UI sebagai `draft without direction` sampai arah tersebut tersedia. Temuan ini adalah audit process/design, bukan permintaan untuk menciptakan identitas baru tanpa konfirmasi.

### 6. [MEDIUM] Teknik dekoratif bertumpuk tanpa alasan per keputusan

- Rule: R-01, R-12, R-13, R-19, R-31.
- Evidence: portal pembuka menggabungkan beberapa radial gradient, dua glow blur, dua ring, box-shadow berlapis, dan tiga animasi di `style.css:37-62`. Hero juga memakai gradient di `style.css:64`, sedangkan kartu dan ikon memakai shadow atau gradient tambahan di `style.css:67`, `99-103`, dan `128-131`. Alasan yang tertulis hanya `restrained UGM maroon, ivory, and soft gold`, bukan alasan fungsi tiap teknik atau batas dosisnya.
- Impact: perhatian pengguna berpotensi tersebar dari tindakan utama, terutama pada layar pembuka; reviewer tidak dapat membedakan identitas, hierarki, dan dekorasi.
- Suggested fix: pertahankan hanya teknik yang punya fungsi jelas, lalu dokumentasikan satu baris alasan untuk portal, focal point, shadow, glow, gradient, dan motion. Hormati `prefers-reduced-motion` yang sudah ada.

### 7. [MEDIUM] Status dan dekorasi menggunakan bahasa live atau siap tanpa sumber state yang terlihat

- Rule: R-09, R-13, R-19, R-31, C-5.
- Evidence: hero menampilkan `SIAP` di `index.html:60`, environment bar memakai `.status-pulse` di `style.css:110`, dan hasil memakai `.live-badge` di `style.css:154`. Pada markup yang dibaca, elemen `.live-badge` tidak ditemukan, sementara status lingkungan baru diisi async oleh `checkEnv()`. Portal juga menjalankan animasi `portal-pulse` untuk ring dekoratif di `style.css:53-58`.
- Impact: istilah status dapat terbaca sebagai kondisi runtime padahal sebagian adalah copy dekoratif, dan indikator visual tidak selalu memiliki status tekstual yang setara.
- Suggested fix: bedakan copy identitas dari status runtime; setiap dot atau badge harus menandai state yang benar-benar ada, dengan teks yang dapat dibaca dan tanpa pulse dekoratif.

### 8. [MEDIUM] Kontras beberapa teks dan kontrol perlu diperbaiki berdasarkan nilai warna aktual

- Rule: R-25, R-32.
- Evidence: source menggunakan warna muted dan border transparan pada kombinasi background gradient atau rgba, misalnya `--muted: #765e62`, `--line: rgba(93, 31, 46, .15)`, `.auth-status` di `style.css:77`, dan `.environment-note` di `style.css:111`. Focus ring memakai `--gold: #96752c` di `style.css:173`, tetapi adjacent background berubah antara cream, putih, dan gold.
- Impact: kontras tidak dapat dinyatakan aman hanya dari deklarasi CSS karena background berbeda per konteks. Border dan focus indicator berpotensi kurang dari 3:1 pada area terang.
- Suggested fix: hitung pair aktual per state dan konteks, lalu gunakan warna solid atau focus treatment yang lolos WCAG AA untuk teks dan 3:1 untuk non-teks.

### 9. [MEDIUM] Dekorasi hero dan portal memakai simbol atau copy generik yang tidak menambah fungsi

- Rule: R-04, R-08, R-31.
- Evidence: markup memakai tanda `P`, panah `→`, dan panah upload `↑` di `index.html:18`, `63`, dan `101`. Panah `→` hanya dekorasi alur, bukan kontrol. Relevansi simbol tidak dijelaskan di source selain copy identitas umum Pandora.
- Impact: elemen visual mengambil perhatian dan menambah vocabulary dekoratif tanpa membantu operasi transkripsi.
- Suggested fix: pertahankan hanya simbol yang membantu memahami alur atau operasi, dan tulis alasan satu baris untuk simbol yang dipertahankan. Jangan gunakan panah sebagai pola button identity.

### 10. [LOW] Komposisi desktop dan mobile menyembunyikan visual utama tanpa mengganti fungsi komunikasinya

- Rule: R-03, R-05, R-20.
- Evidence: `.hero-art { display: none; }` pada mobile di `style.css:195-199`. Pada desktop visual tersebut menjelaskan alur `SUARA` ke `TEKS YANG DAPAT DICARI` di `index.html:58-64`, tetapi pada mobile tidak ada ringkasan alternatif.
- Impact: mobile kehilangan bagian identitas dan penjelasan alur, bukan hanya menyusun ulang layout.
- Suggested fix: buat versi mobile yang lebih ringkas atau berikan teks alur yang tetap terlihat; jangan sekadar menghapus visual bila informasi tersebut masih dibutuhkan.

### 11. [LOW] Navigasi hasil dan riwayat belum memiliki penanda active atau focus yang cukup eksplisit

- Rule: R-24, R-32, C-4.
- Evidence: link nav memiliki target yang benar di `index.html:40-43`, tetapi state section aktif tidak ditandai. Tab hasil mengubah `aria-selected`, namun tidak menetapkan `tabindex` roving atau `aria-controls` yang konsisten pada panel untuk semua state di `app.js:352-371`. Focus global memang ada di `style.css:173`, tetapi select memakai `outline: none` di `style.css:139` dan menggantinya hanya dengan `:focus` biasa di `style.css:140`.
- Impact: pengguna keyboard mendapat konteks active yang terbatas dan focus behavior yang tidak sepenuhnya mengikuti pola tab ARIA.
- Suggested fix: tetapkan pola tab keyboard lengkap, `tabindex`, panel association, dan focus state yang konsisten untuk select serta semua kontrol.

### 12. [LOW] Halaman mengandalkan inline HTML injection untuk status server

- Rule: C-4, maintainability review.
- Evidence: `checkEnv()` mengisi `#env-status` lewat `innerHTML` di `app.js:86` dan `app.js:102`, termasuk nilai `router.error` dalam atribut `title` di `app.js:83`.
- Impact: status dinamis lebih sulit diaudit dan aman hanya jika seluruh nilai dari API diperlakukan sebagai trusted. Error yang panjang juga dapat menjadi tooltip yang sulit dibaca atau tidak tersedia untuk keyboard.
- Suggested fix: buat node status dengan `textContent`, class state terpisah, dan elemen detail yang dapat dibaca, tanpa menyusun HTML dari response server.

## Blocker verifikasi runtime

- Browser verification belum dapat dijalankan karena server tidak berhasil start dengan launcher environment `.venv-test`: `ModuleNotFoundError: No module named 'itsdangerous'`.
- System Python memiliki FastAPI, Uvicorn, ItsDangerous, dan python-multipart, tetapi server belum dijalankan dengan environment tersebut pada audit ini.
- Karena runtime tidak tersedia, ukuran visual, computed contrast, overflow aktual, click-through, dan console error belum dapat diklaim terverifikasi melalui browser.

## Urutan perbaikan yang disarankan

1. Temuan 1, 2, dan 3, karena memblokir alur utama dan akses dasar.
2. Temuan 4 dan 11, karena menyangkut keyboard serta semantics.
3. Temuan 8, lalu 6 dan 7, setelah computed style dapat diverifikasi di browser.
4. Temuan 5, 9, 10, dan 12 sesuai keputusan arah visual dan batas scope.
